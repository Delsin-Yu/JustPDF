## 五、优先级与首批范围

| 优先级 | 特征 | 示例 |
|--------|------|------|
| P0（先接） | 只读浏览、轻量交互、无文件/无实时数据 | 商品/新闻/文章详情页、只读列表 |
| P1（小项目可直接接） | 输入/编辑/表单，但数据量小 | 简单输入框、短文本编辑 |
| P2（实现P0 P1后再接） | 大列表、文件/媒体、实时流 | 图片编辑、视频播放、长表单 |
| P3（特殊处理） | 敏感页面、多 Ability 联动 | 登录页、支付页、多页创建流 |

- [ ] 首批接续场景已圈定（按照工作量拆分，优先 P0、P1，小项目可考虑一次完成，大项目不一次铺开）

## 六、数据范围边界（必提醒项）

> 用户默认认知是"接续 = 数据全都带过去"，而 skill 默认方案**只迁移页面的可变状态及关联文件**。该边界必须显式告知，不得只在执行报告里被动提及。

- [ ] 已向用户显式说明**默认数据范围**：仅迁移页面的可变状态及关联文件（如笔记的标题/正文/图片文件/滚动/光标），**本地库中的文件不迁移**
- [ ] 已显式确认是否需要**整库/可选数据迁移**：□ 不需要（按默认方案） □ 需要（按下述推荐顺序选型）
  - **首选：文件云同步 + 数据标识重拉取**（`references/data-migration-strategies.md` 方式四：`want` 只传数据标识，业务后端/云侧拉取——迁移载荷最小、无传输上限风险）
  - **次选：整库随接续传输**（方式二 + 方式三组合：全量数据进 DDO、文件经 Asset 根属性传输；对端按记录 ID 合并入库，须处理合并冲突与传输体量，必须将真机验证列入人工验证清单中）

## 附录 B：源端退出方案说明

| 推荐方案 | 含义 | 实现方式 |
|---------|------|---------|
| **退出** | 迁移完成后源端应用退出（系统默认行为） | 无需配置（`SUPPORT_CONTINUE_SOURCE_EXIT_KEY` 默认 true） |
| **不退出** | 源端应用保留且业务继续，无额外处理逻辑 | `SUPPORT_CONTINUE_SOURCE_EXIT_KEY = false`，业务不中断 |
| **不退出，暂停** | 源端应用保留，但进入暂停状态，常用于播放/听书类业务 | `SUPPORT_CONTINUE_SOURCE_EXIT_KEY = false` + 源端页面暂停逻辑（如 `player.pause()`） |
| **不退出，返回** | 源端应用保留，但回到前置界面或主界面，常用于会议类业务 | `SUPPORT_CONTINUE_SOURCE_EXIT_KEY = false` + 源端返回到所需页面逻辑 |
| **应用按需适配** | 官方未给固定建议，由应用按体验决策 | 与用户确认后从上述方案中选择，确认结果记入《接续场景清单》 |

**保留源端（"不退出""不退出，暂停""不退出，返回"，以及"应用按需适配"情况下用户确认为保留的方案）时必须评估并发写冲突策略**
