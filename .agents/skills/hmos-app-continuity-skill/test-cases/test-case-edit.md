# tc_003：内容编辑页面接续

## 基本信息

- **编号**：tc_003
- **标题**：内容编辑页面接续
- **文件名**：test-case-edit

## 用户指令

> 给笔记编辑器页面添加接续内容，用户写的所有内容必须完整带过去，继续写。


## 重点验证标准

| ID | 标准 | 典型失败行为 |
|---|--------|---------------------------|
| S1 | 执行流程按[核验 → 确认 → 设计 → 改码 → 自检 → 报告]走；缺少条件靠引导补充，不依靠多轮执行试错 | 跳步/漏步（如跳过核验、确认直接改码）；缺必要条件时不向用户提问引导，靠一轮轮试错改码"补窟窿" |
| S3 | 先确认用户场景以及附件确认项（页面栈、源端如何处理），未答清不修改代码 | 不提问就默认按自己理解直接开工；用户只要求评估时跳过确认直接改代码 |
| S4 | 完成报告含人工清单；未完成不声称已联调完成 | 只报"做完了/全部完成"，不列真机组网、冷/热启动实测等人工步骤；遗漏关键路径仍称"所有页面都接好了" |
| S5 | 按场景加载对应方案和示例，不混入多余内容 | 把非当前场景的方案和示例混入当前场景输出 |
| S6 | 改码后开发者原有代码可用，不影响原有功能 | 破坏原有编辑、保存、播放、新建等正常流程 |
| S7 | 若接续图片、文件、媒体文件等，接续后相关文件可打开、可播放、可用 | 本地文件只传路径/URI 引用，对端读不到文件、无法打开/播放；在线媒体硬传文件内容或把大文件塞进 `want.parameters` |
| S8 | 只进行需要传输页面的数据处理、Ability的数据传输、配置文件的代码生成；不另起工程、修改原有架构 | 修改与接续无关的页面代码（如首页列表）；另起独立工程或大范围重构原有架构 |
| S9 | 须先打开本Skill对应`assets/`模板；读不到则中止，禁止凭记忆重写 | 未判断skill结构完整就开始工作；凭记忆手写代码，用出不存在的方法/错误签名 |
| S12 | 完成报告字段齐全 | 只说"做完了"或只列改动清单，缺修改摘要、引导确认摘要、验证结果、人工清单等字段 |
| S13 | 环境能编译则要求编译通过；不能编译则在报告写明，不谎称已通过 | 使用不存在的方法/类型/导入导致编译 ERROR；环境不能编译时谎称"编译已通过" |
