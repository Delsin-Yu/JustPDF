# 测试提示词（test-prompts.md）

> 验证功能的测试场景索引，包含各场景的测试输入提示词和预期行为。

## 基础功能测试

### 场景 1：原生 UI 页面接续（tc_001: test-case-ui-native.md）

```
帮我给应用加上跨设备接续。
```
预期行为：应用能正常触发接续，接续后Tab列表选择的页面、页面滚动位置、页面中的状态变量正确保留。

### 场景 2：WebUI 页面接续（tc_002: test-case-ui-web.md）

```
我们的 H5 文章页面需要支持跨设备接续，用户在看一篇文章的时候可以转到平板上继续看，滚动位置、页面状态都要保留。
```
预期行为：应用能正常触发接续，接续后目标端打开同一篇文章、滚动位置正确恢复，可继续阅读；H5 内部状态的恢复边界在报告中如实说明。

## 场景测试

### 场景 3：内容编辑页面接续（tc_003: test-case-edit.md）

```
给笔记编辑器页面添加接续内容，用户写的所有内容必须完整带过去，继续写。
```
预期行为：应用能正常触发接续，接续后笔记文本、图片内容完整带过去，滚动位置等编辑状态正确恢复，可继续编辑；新建笔记不显示旧数据、保存不覆盖原笔记。

### 场景 4：媒体播放页面接续（tc_004: test-case-playback.md）

```
添加应用接续功能。用户在手机上看到某个位置，接到平板后继续从同一位置播放。
```
预期行为：应用能正常触发接续，接续后视频从触发接续的位置继续播放，播放状态与播放列表正确继承。

### 场景 5：页面栈迁移（tc_005: test-case-navigation.md）

```
添加应用接续功能，注意用户从首页 → 分类 → 商品详情 → 下单确认，在这个路径上触发了接续，目标端要停在"下单确认"页面，按返回键依次回到商品详情 → 分类 → 首页。
```
预期行为：应用能正常触发接续，接续后目标端停在"下单确认"页面，按返回键依次回到商品详情 → 分类 → 首页，各层页面入参正确保留。

### 场景 6：源端保留不退出（tc_006: test-case-source.md）

```
我的备忘录项目希望在手机上写了半篇文档，能接续到平板上写。但手机上的应用不要关，等我确认平板接收完了、数据都对了，再手动关手机这边。帮我实现这个功能。
```
预期行为：应用能正常触发接续，接续后平板端可继续编辑，手机端应用不退出、进度与草稿原状保留。

## 边界条件测试

### 场景 7：API 版本过低（tc_007: test-case-unsupported-sd.md）

```
帮我把这个应用的详情页接到跨设备接续功能上，用户可以在不同设备上接着看文章。
```
预期行为：检测到 API 版本低于 12 后中止改码流程，向用户说明版本约束与可选方案，等用户决策后再行动。

### 场景 8：未要求接入不改码（tc_008: test-case-guide-unspecified.md）
提示词1：
```
我听说鸿蒙应用可以跨设备接续，这是怎么实现的？
```
预期行为：识别用户意图为原理询问，按场景讲解应用接续实现方式，不修改任何代码。

提示词2：
```
这个手机端的应用代码如何迁移到PC生态开发
```
预期行为：识别到用户意图为跨设备开发，与 Skill 无关，主动拒绝并说明 Skill 功能边界。

提示词3：
```
我们的项目可以接入应用接续功能吗？先给我评估报告，不要修改代码。
```
预期行为：识别到用户只想要评估，根据用户要求只出评估报告，不修改代码。
